# AI-10: Task Extraction and Confirmed Planning

Date: 2026-10-28.
Status: implementation started; planning and extraction are not implemented.

## Owner-approved delivery

The owner approved incremental local implementation with verification and local
commits, including the missing P-06 foundation and the complete browser flow:
source selection, editable task proposals, plan preview, exact confirmation,
calendar sessions and replanning. No application migration, restart, deployment,
real provider request or automatic background review is authorized.

Confirmed behavior:

- Save weekly allowed work windows; request-specific windows do not overwrite them.
  Ask when no windows are available. Use the profile timezone.
- Default work/break lengths are editable 45/15 minutes. Permit sessions of at
  least 15 minutes and a smaller final remainder.
- Elapsed sessions never establish progress or completion. Use explicit remaining
  work/user-reported progress. Parents and subtasks must not duplicate effort.
- Any future unpinned task session, including a manually created session, may be
  proposed for rescheduling. Pinning protects it. Started/past sessions, personal
  appointments and official occurrences are protected during general replanning.
- Dependencies are cycle-safe and advisory for manual task actions. Planning must
  respect predecessor order; parent/child relationships alone do not imply order.
- Preview schedulable work and the exact unplaced remainder. Partial plans require
  explicit confirmation; never claim an unproven optimum or impossibility.
- Extracted tasks remain independent of page checkboxes and database records.
  Preserve source locations, ambiguity, possible duplicates and labeled estimates.
- All related changes and the replay receipt commit in one transaction after
  availability, source, task and preference revalidation. Changed preconditions
  reject the complete proposal and require a new preview and confirmation.
- Only configured/expected official sources need coverage. Missing/stale coverage
  permits conditional previews, not affected plan application.

## Implementation sequence

1. Task dependencies and explicit page links, preserving existing task APIs.
2. Task work sessions, complete busy/free/conflict queries and manual scheduling.
3. Versioned weekly preferences and explicit remaining-work accounting.
4. Deterministic planning/replanning with unmet-work explanations.
5. Typed task reads/extraction and confirmed task/plan actions through AI-07.
6. Browser settings, source/task review, session management and plan confirmation.
7. Integrated acceptance, documentation and final local verification.

Each increment includes meaningful service, persistence and HTTP tests; browser
changes include relevant UI tests. Use synthetic provider responses only. Run Ruff,
format checks, Pyright and pytest for backend changes, frontend lint/typecheck/build/
tests for browser changes, and quiet Compose validation. Preserve dated evidence;
checks not run are never reported as passing.
