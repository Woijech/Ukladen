## Implemented transport

All paths are relative to `/api/v1/ai`. Existing active/completed session, owner,
Origin, CSRF and `Cache-Control: no-store` rules apply. Owner identity is never
accepted in a body. Existing synchronous submission and forward history remain.

| Method / path | Contract |
| --- | --- |
| POST /conversations/{id}/messages/stream | Existing `MessageSubmit`: UUID submission ID, message and optional source_scope; SSE response |
| GET /conversations/{id}/state | Current owned conversation and latest retained run; reconnect does not submit |
| GET /conversations/{id}/messages?recent=true | Newest bounded window in ascending sequence; optional exclusive `before` cursor loads older windows |
| GET /preferences | Instructions and version; absent settings are empty/version zero |
| PUT /preferences | `instructions`, `expected_version`; explicit version-checked replacement, empty text clears instructions |
| POST /sources/read | Typed existing source queries plus UI-only `RecordRead`; current ownership/trash/version checks and bounded evidence |
| GET /usage | 7/30-day preset or inclusive date_from/date_to, at most 31 civil days; recent-run limit 1–100/offset 0–10000 |

SSE exposes only `run` (safe run metadata), `progress` (model/tool name, number,
status), `delta` (visible text/message ID), `recover` (run ID) and `done`.
Framework state snapshots, arguments, tool bodies, credentials and reasoning blocks
never cross this transport. The existing LangChain graph streams messages/values;
only an explicit visible-text allowlist is forwarded. Partial tool arguments are
never dispatched by the UI. Model retries/new messages reset transient answer text.
SSE uses `Cache-Control: no-store, no-transform` to preserve privacy while preventing
the local Next.js proxy's gzip buffering from delaying small fragments. Other
frontend responses retain their existing compression behavior.

Admission records the existing submission/run before execution. Eight process-local
stream workers and eight existing bounded model/tool slots cap concurrent work.
Each stream has a 128-event transient queue and at most 64 KiB emitted text across
bounded model calls. Slow/disconnected consumers recover canonical messages and
run state; transient text is not a second persistent chat copy. The existing
60-second run and tool/attempt limits remain. Cancellation/deletion/expiry checks
fence streamed fragments as well as final messages/checkpoints. Already admitted
external calls may finish; cancellation is not a provider billing rollback.

The client retains the exact pending submission ID/payload while its outcome is
uncertain. Recovery reads stored state; explicit resend uses the same ID. Reload
or browser return uses the selected chat URL and current server state, not browser
storage. Failed/interrupted processes retain the existing conservative recovery
policy. The UI's polling is a recovery path, not simulated token streaming.

## Settings and sources

Instructions are at most 8192 UTF-8 bytes and are loaded from the current owner
before each model dispatch. They augment server policy as lower-priority personal
preferences and never create grants or hard planning settings. Their versioned
table survives chat deletion/expiry; user deletion cascades it. Ordinary messages
are not saved as instructions. API keys use AI-02's encrypted connection API;
forms clear plaintext on submission and unmount. Models/connections remain immutable
within a chat. No model/credential fallback or provider activation is added.

Automatic source discovery remains the default. Explicit selection permits up to
20 pages/materials/databases combined, plus calendar. An empty selection permits
no source reads; selecting a database does not implicitly permit its page bodies.
This is the existing AI-03 server-enforced scope, not only a prompt suggestion.
The viewer reads current bounded text/schema/record/calendar data; changed versions,
unavailable sources, partial coverage and freshness warnings remain visible.
Record previews show five fields at a time and at most 400 characters/value;
they add no advertised agent tool. Text renders through React, never raw HTML.

## Usage and historical estimates

`ai` queries the owned durable run/attempt journals in a read-only repeatable-read
snapshot with a five-second statement timeout. Profile timezone determines civil
date boundaries, including DST. Run counts use admission day; attempts/tokens use
attempt start day. Retries, failed and cancelled attempts remain separate charges
when the provider reports usage. Independent activity retention filters apply even
before physical cleanup. Reports contain no prompt, source body, key or arguments.
An explicit retention_partial flag/warning distinguishes expired parts of a
selected period from an observed period with no requests.

Input/output totals become null when any retained attempt lacks that measurement;
known subtotals and unknown-attempt counts remain explicit. No extra reasoning or
cached subsets are added to provider input/output totals. Fake totals stay separate.
Recent runs paginate independently of summary/daily/model totals. Index status
states lexical-only; no semantic index is implied by infrastructure availability.

An optional model-offering `price` contains `date`, three-letter `currency`, and
nonnegative decimal `input_per_million` / `output_per_million` rates (at most 1000000).
Admission snapshots it onto the run. Later catalog changes cannot reprice that run.
Missing prices/tokens remain unpriced; known estimates are subtotaled by currency,
never summed across currencies or represented as invoices/global account balance.
Per-run details expose the saved tariff and estimate for retained known attempts.
No actual price, spending authorization or external balance lookup is inferred.

Migrations 0026/0027 preserve existing messages and unpriced runs. Downgrade refuses
nonempty instructions/non-null prices instead of discarding retained user data.
See [persistence](ai-persistence.md) and [connections](ai-connections.md).

## UI and limits

`/workspace/ai` and `/workspace/ai/usage` reuse the existing account-scoped shell,
A1 identity, theme tokens and dialogs. Chats have separate URL selections, a
paginated history and newest-message windows. Source selection, current source
inspection, model/connection controls, saved instructions, accessible usage tables
and mobile/keyboard flows are implemented. Logout/identity changes unmount private
forms, abort stream/source reads and discard their query client. No private browser
storage or new frontend dependency is introduced.

The backend stays disabled until the existing explicit activation prerequisites are
met. UI availability is not proof of a connected provider. The fake model is labeled
as a fixed demonstration; text-only/nonstreaming offerings do not acquire tools by
being displayed. Provider quality, production proxy/load behavior and a live account
smoke remain unverified. Input budgets still cover schemas/history/instructions as
well as the message; oversized requests fail instead of silently dropping context.
