# AI-06: Hybrid Retrieval and Complete-Source Processing

Status: implemented locally; disabled/unactivated in the application. No production
migration, deployment or real LLM request was performed. Owner decisions: 2026-10-25.
Final verification is recorded below; earlier dated results retain their original scope.

## Owner scope and product policy

All active owned pages (including record pages) and extractable materials participate
in asynchronous indexing after operator activation. Explicit request source selection
remains authoritative. Calendar and database properties use existing structured
reads. Hybrid retrieval is AI-only; ordinary search HTTP behavior is unchanged.

The development priority is the complete product capability. No subscriptions,
paywalls, monthly request/token allowances or document-analysis quotas are added.
The existing unlimited access-policy seam and owner usage accounting remain available
for future work. Parser security, concurrency, retries, context windows and transport
bounds remain technical safeguards. Long-source processing crosses those boundaries
automatically rather than asking the user to send manual continuation messages.

## Located extraction

Revision `0028_material_locations` adds extraction locations/revision to the derived
material text table. The existing isolated parser preserves actual one-based PDF
page and PPTX presentation-order slide numbers, including empty pages/slides in the
numbering. Character ranges refer to the extracted Unicode text. DOCX/TXT/Markdown
use text ranges; no rendered DOCX page numbers or OCR are invented.

The processing port returns text plus locations and publishes them with the material
completion transaction. Existing downloads, upload/extraction security boundaries,
file retention and original content are preserved. After retrieval is activated,
legacy extracted files are queued for one preserving re-extraction; originals remain
available. Source inspection returns actual locations for the displayed range.

## Index and hybrid retrieval

Revision `0029_search_chunks` owns derived generations, leased source state and chunks
under `search`. A generation identifies provider/model/revision/dimensions,
normalization, tokenizer revision and chunker revision. The initial provider is the
pinned local AI-05 E5-small runtime. Tokenization is real, includes the passage prefix
and specials, and does not load ONNX just to count tokens. Chunks target 384 tokens,
with up to 64 tokens overlap, and preserve block/page/slide ranges and SHA-256 hashes.

A durable canonical scan discovers new/changed sources and lost broker deliveries.
The dedicated `embeddings` queue handles four chunks at a time with one worker
process. Claim/compute/publish use separate short transactions, canonical owner/version
checks, leases and fencing. Partial batches never become searchable before final
publication. Expired workers cannot publish; three failed/crashed attempts produce
an explicit failed state and owner retry. Trash/purge cleanup removes derived rows;
queries reject trashed, foreign, disabled-owner and outdated content immediately.

Queries embed outside source transactions, then read current owner/version-filtered
lexical/vector candidates in one snapshot. Exact pgvector cosine ranking and lexical
ranking use deterministic reciprocal-rank fusion (constant 60). Located chunk results
replace duplicate document previews. Semantic failure preserves lexical results with
an explicit warning. Index incompleteness differs from a successful search with no
matches. Search snippets always have partial coverage and a bounded transport envelope.
No ANN index, reranker, new service, bookmark fetching or embedding API is added.
Changing the model/chunker creates a separate generation; incompatible vector spaces
are never mixed. Previous generations retain canonical-independent derived data.

## Complete-source mode (owner option 2B)

The existing message/stream endpoints accept `full_sources: true` with explicit
`source_scope.page_ids` / `material_ids`. Select the pages/files in the existing source
picker and enable **Разобрать выбранные страницы и файлы целиком**. Calendar/database
property selections require their normal tools instead. Scope has no document-count
allowance. A missing selection returns an actionable validation error.

Admission atomically creates the normal owned run, original user message and durable
`ai_document_jobs` row (revision `0030_ai_document_jobs`). An idempotent replay returns
the same run. The stream acknowledges queued work; processing continues without an
open browser/HTTP connection on the `ai-documents` queue. A durable scan recovers
broker gaps and expired leases. The existing cancel endpoint and conversation deletion
fence later responses. Files still being extracted are awaited without a model call.

Each dispatch reads the next UTF-8-safe text range, invokes the same logical assistant
through LangChain `create_agent`, then commits its concise evidence notes and cursor.
Successive combination steps merge notes with source attribution; final synthesis
appends one assistant message to the original chat. Step persistence owns recovery;
there is no custom model/tool loop or extra agent subsystem. Model execution holds no
source transaction. All available text is visited, independent of foreground run/tool
budgets. Individual model calls retain a deadline and finite failure retries.

Every step, publication and real-provider dispatch rechecks source versions, owner,
conversation lifetime, cancellation and connection access. Source changes fail the
old analysis and discard derived notes; they do not mix versions. Disabled owners
stop processing. Provider rate-backoff delays work without consuming an error retry.
Failed/crashed steps stop after three attempts; partial work is never labeled a
completed analysis. Final source references preserve versions; complete coverage means
all available extracted text was processed, not all original visual content.

All provider attempts, including more than four calls across successive steps, use
the existing usage ledger and price snapshots. Foreground anti-loop bounds remain
separate. No alternative credential/model or synthetic fallback replaces an unavailable
real connection. Subsequent ordinary chat requests can use the previous analysis only
after its sources are revalidated against the current explicit scope and versions.

Intermediate notes and final synthesis are lossy model outputs. Reading every text
range is not proof of exhaustive findings or answer correctness. Real-model comparison
quality remains unverified; routine verification uses synthetic models/transports.

## API and interface

- `GET /api/v1/ai/runs/{run_id}/document-progress`: owned phase, character progress,
  successful step count and a sanitized error category; null for foreground runs.
- `GET /api/v1/ai/sources/{page|material}/{id}/index`: current version and compact
  pending/processing/ready/failed/unavailable state.
- `POST .../index/retry`: authenticated CSRF-protected retry of failed indexing.

Existing chat polling displays saved progress after reopening/reloading. The source
viewer shows actual PDF/slide locations and index status, with retry on failure.
No separate index administration screen or subscription interface is introduced.

## Optional deployment wiring; activation remains separate

Base Compose defines opt-in `ai` and `embeddings` worker profiles. Ordinary workers
keep their queues and do not load models. `docker-compose.retrieval.yml` adds the
optional CPU image/model mount to the API and configures scanning; its application
flag/real provider activation is unchanged. Set `SEARCH_EMBEDDINGS_DIRECTORY` to the
already verified artifact directory. Inference never downloads models at startup.

`docker-compose.ai.yml` mounts the private catalog read-only into API and the opted-in
AI document worker. Embedding/material workers and Beat receive no catalog mount;
the embedding consumer explicitly clears AI configuration. Home overrides retain
private ports and the consumer-specific secret boundary. With activation separately
authorized, combine the base/home (if used), AI catalog and retrieval overlays and
select the two worker profiles. Apply migrations only to the intended reviewed target.

Do not enable real provider traffic merely to test deployment wiring. AGENTS.md still
requires concrete bounded owner approval for coding-agent provider use, including free
quotas. No application flag, secret file or running application process was changed.
